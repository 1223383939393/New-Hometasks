 try-catch — это механизм обработки исключений. Он позволяет программе не «падать» при ошибке, а корректно на неё реагировать: вывести понятное сообщение, повторить попытку, записать в лог, продолжить работу. 
 
 Представь: пользователь ввёл "abc" вместо числа, файл не найден, деление на ноль. Без обработки программа просто аварийно завершается. С обработкой — можно объяснить пользователю, что пошло не так.
  Пример: 
```csharp
  public class Main { 
	  public static void main(String[] args) { 
		  int a = 10; 
		  int b = 0;
		   try { 
			   System.out.println(a / b); 
		   } catch (ArithmeticException e) { 
			   System.out.println("Ошибка: деление на ноль!"); 
		   } 
		   System.out.println("Программа продолжает работу");
		}
	} 
	
```
Что пишется в блоке try {}, а что пишется в блоке catch {}? в блоке try пишется та часть кода которую мы хотим проверить, в блоке catch пишется код который обрабатывает исключение, сообщение

Что за разделение Unchecked и Checked? В чем разница? 
- **Checked (проверяемые)** — компилятор _требует_ их обработать (`try-catch` или `throws`). Пример: `IOException`, `SQLException`. Возникают при работе с внешними ресурсами.
    
- **Unchecked (непроверяемые)** — наследники `RuntimeException`. Компилятор не заставляет их ловить. Пример: `NullPointerException`, `ArrayIndexOutOfBoundsException`. Обычно это ошибки логики программы.

Почему нельзя просто использовать Exception в catch? 
Потому что ты ловишь _всё_, включая непредвиденные ошибки, и можешь пропустить важные проблемы. Лучше ловить конкретно то, что ожидаешь, а `Exception` оставить на крайний случай.
